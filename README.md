# متحكم Necklace

لوحة تحكم ويب محلية باللغة العربية لسماعة **Oraimo Necklace Lite** (`28:52:E0:0F:92:0A`). تعمل على Linux.

```
المتصفح  ──HTTP/WebSocket (127.0.0.1)──▶  الوكيل المحلي (Python)  ──D-Bus──▶  BlueZ / MPRIS  ──Bluetooth──▶  السماعة
```

المتصفح لا يتواصل مع Bluetooth مباشرة. كل الاتصال يمر عبر **الوكيل المحلي**، والوكيل يستخدم واجهات النظام الموثّقة فقط (BlueZ وMPRIS عبر D-Bus). لا يرسل الوكيل حزمًا خامًا، ولا يتعامل مع قناة JieLi الخاصة.

> التطبيق مبني على ما أثبته تحليل الالتقاط [`docs/necklace_report.md`](docs/necklace_report.md). حالة كل قدرة موثّقة في [`docs/protocol-status.md`](docs/protocol-status.md).

---

## 1. المتطلبات

- Linux مع جلسة سطح مكتب. يحتاج التحكم في المشغل إلى ناقل جلسة المستخدم (MPRIS).
- Python 3.9 أو أحدث.
- الحزم: `aiohttp` و`dbus-fast` (في `agent/requirements.txt`).
- اختياري: `evdev` لمراقبة أزرار السماعة (في `agent/requirements-optional.txt`).
- متصفح حديث: Chrome أو Chromium أو Firefox أو Edge.

## 2. متطلبات Bluetooth على Linux

- محول Bluetooth يعمل وغير محظور: `rfkill list` ثم `rfkill unblock bluetooth` إذا لزم.
- خدمة الصوت **PipeWire**، مع `wireplumber` و`libspa-0.2-bluetooth`. PipeWire هو من يوفر A2DP وHFP، ومن يمرر قراءة البطارية إلى BlueZ.
- لكي تظهر البطارية، يجب أن يسجّل PipeWire «مزوّد بطارية» لدى BlueZ. في بعض إصدارات BlueZ القديمة يتطلب ذلك إضافة `Experimental = true` في `/etc/bluetooth/main.conf` ثم إعادة تشغيل الخدمة.

## 3. متطلبات BlueZ

- يُنصح بـ BlueZ 5.60 أو أحدث (تم التطوير على 5.72).
- الواجهات المستخدمة: `org.bluez.Adapter1` و`Device1` و`MediaControl1` و`MediaTransport1` (الخاصية `Volume`) و`Battery1`.
- الخدمة يجب أن تعمل: `systemctl status bluetooth`.

## 4. التثبيت

```bash
cd necklace-controller
python3 -m venv .venv
. .venv/bin/activate
pip install -r agent/requirements.txt
# اختياري: مراقبة أزرار السماعة
pip install -r agent/requirements-optional.txt
```

## 5. تشغيل الوكيل المحلي

شغّل الوكيل **بحسابك العادي**، لا بحساب root، لأنه يحتاج إلى ناقل جلسة سطح المكتب:

```bash
python -m agent
# خيارات:
python -m agent --port 8765 --device 28:52:E0:0F:92:0A --adapter hci0 --log-file ~/.cache/necklace-agent.log
```

- يستمع الوكيل على `127.0.0.1:8765` فقط، ويرفض العناوين الأخرى إلا مع الخيار الصريح `--allow-non-local` (غير مستحسن).
- السجلات التفصيلية تُكتب في الطرفية أو في ملف `--log-file`. الواجهة لا تعرض أي stack trace.

للتشغيل التلقائي عند تسجيل الدخول، استخدم خدمة systemd للمستخدم في `~/.config/systemd/user/necklace-agent.service`:

```ini
[Unit]
Description=Necklace local Bluetooth agent
After=pipewire.service

[Service]
WorkingDirectory=%h/necklace-controller
ExecStart=%h/necklace-controller/.venv/bin/python -m agent
Restart=on-failure

[Install]
WantedBy=default.target
```

ثم نفّذ: `systemctl --user enable --now necklace-agent`.

## 6. تشغيل واجهة الويب

الوكيل نفسه يقدّم الواجهة. افتح في المتصفح:

```
http://127.0.0.1:8765/
```

لا حاجة إلى خادم ويب آخر. الخطوط والأيقونات مضمّنة محليًا، ولا تُحمَّل أي موارد من الإنترنت.

## 7. إقران السماعة

1. ضع السماعة في وضع الإقران. راجع دليلها؛ غالبًا يكون ذلك بضغطة مطوّلة على زر التشغيل وهي مطفأة.
2. نفّذ:

```bash
bluetoothctl
power on
agent on
default-agent
scan on          # انتظر ظهور 28:52:E0:0F:92:0A  oraimo Necklace Lite
pair 28:52:E0:0F:92:0A
trust 28:52:E0:0F:92:0A
connect 28:52:E0:0F:92:0A
scan off
```

بعد ذلك يمكنك استخدام زر «اتصال» أو «إعادة الاتصال» في اللوحة.

## 8. استكشاف الأخطاء

| الرسالة في الواجهة | السبب المحتمل | الحل |
|---|---|---|
| تعذر الوصول إلى الوكيل المحلي | الوكيل لا يعمل | `python -m agent` |
| تعذر الوصول إلى خدمة Bluetooth على النظام | bluetoothd متوقف | `sudo systemctl start bluetooth` |
| تعذر الاتصال بناقل النظام D-Bus | بيئة غير قياسية أو حاوية | شغّل الوكيل على الجهاز نفسه وليس داخل حاوية |
| تم رفض الإذن بالوصول إلى Bluetooth | سياسة D-Bus تقيّد BlueZ | `sudo usermod -aG bluetooth $USER` ثم سجّل الدخول من جديد |
| Bluetooth متوقف على هذا الجهاز | المحول مطفأ أو محظور | `bluetoothctl power on` أو `rfkill unblock bluetooth` |
| السماعة غير مقترنة بهذا الجهاز | لم تُقرن بعد | راجع القسم 7 |
| السماعة غير متاحة | مطفأة أو بعيدة أو متصلة بجهاز آخر | شغّلها وقرّبها، وافصلها عن الهاتف |
| لا يوجد مشغل وسائط يدعم MPRIS | لا يوجد مشغل مفتوح، أو الوكيل يعمل كـ root | افتح مشغلًا، وشغّل الوكيل بحسابك |
| البطارية «غير معروفة» والسماعة متصلة | PipeWire لم يسجّل مزوّد البطارية | راجع القسم 2. تحقق عبر `bluetoothctl info 28:52:E0:0F:92:0A` (سطر Battery Percentage) |
| مستوى الصوت غير متاح | لا توجد قناة A2DP، أو BlueZ لا يعرض `Volume` | شغّل صوتًا مرة واحدة، وتأكد أن `bluez5.enable-hw-volume` مفعّل في PipeWire |
| أزرار السماعة «غير معروف» | `evdev` غير مثبت، أو لا توجد صلاحية قراءة `/dev/input` | راجع ملاحظات الأمان أدناه قبل منح الصلاحية |

تفاصيل الأخطاء الكاملة موجودة في مخرجات الوكيل أو في ملف `--log-file`.

## 9. الميزات المدعومة

كل ميزة مفعّلة تستدعي عملية حقيقية في الوكيل. لا يوجد زر يغيّر شكل الواجهة فقط.

| الميزة | الواجهة المستخدمة | ملاحظة |
|---|---|---|
| حالة الاتصال والاسم والعنوان ونوع الاتصال | `Device1` | تحديث فوري عبر إشارات D-Bus وWebSocket |
| اتصال / إعادة اتصال | `Device1.Connect` (وقبله `Disconnect` عند إعادة الاتصال) | |
| تشغيل / إيقاف مؤقت | MPRIS `Play`/`Pause` لمشغل الوسائط المحلي | السماعة لا تحتوي على مشغل (الهدف من الفئة 2). زرها يتحكم بمشغل هذا الجهاز، والتطبيق يفعل الشيء نفسه |
| حالة التشغيل | MPRIS `PlaybackStatus` | تُعرض «غير معروف» إن لم يوجد مشغل |
| مستوى الصوت 0–100% | `MediaTransport1.Volume` (AVRCP 0–127) | القراءة مؤكدة في الالتقاط. الكتابة تُعرض «غير معروف» حتى يتحقق منها الوكيل أثناء التشغيل |
| رفع الصوت / خفض الصوت | الخاصية نفسها ± 8 | |
| البطارية | `Battery1.Percentage` | مصدرها HFP، بدقة 10% |
| حالة بث A2DP | `MediaTransport1.State` | |
| أزرار السماعة (اختياري) | قراءة فقط لجهاز الإدخال الذي ينشئه BlueZ لـ AVRCP | بدون grab وبدون كتابة |
| التشخيص | كل ما سبق | يفرّق بين «متاح» و«معلن فقط» |
| سجل الأحداث | داخل الوكيل (آخر 500 حدث) | مسح السجل وتصديره بصيغة JSON أو نص |

## 10. الميزات غير المدعومة

- **كتم الصوت:** لا توجد واجهة كتم مؤكدة. الزر معطّل ومعه شرح السبب.
- **التالي / السابق / الإيقاف:** لم تظهر في الالتقاط.
- **HID:** معلن في SDP فقط، ولم يُتبادل أي تقرير.
- **المعادل الصوتي، تخصيص الأزرار، الرسائل الصوتية، تحديث البرنامج الداخلي:** غير متاحة للتحكم حاليًا. تحتاج إلى تحليل بروتوكول JieLi الخاص وإرساله، وهو خارج النطاق. تظهر في «التحكم المتقدم» كمرجع للقراءة فقط (خريطة أوامر + فاحص إطارات من الالتقاط)، بلا أدوات تحكم.
- **قناة JieLi (RFCOMM 10):** محظورة عمدًا. لا تُفتح ولا يُكتب إليها.

## 11. ملاحظات الأمان

- الوكيل يستمع على `127.0.0.1` فقط افتراضيًا. **لا تعرضه على الشبكة.**
- يرفض الوكيل أي طلب يحمل ترويسة `Host` غير محلية (حماية من DNS rebinding)، وأي `Origin` مختلف عن الواجهة نفسها، ويشمل ذلك WebSocket.
- الطلبات التي تغيّر الحالة يجب أن تكون JSON، ولا يُمنح CORS لأي موقع آخر.
- الإجراءات المسموح بها قائمة بيضاء ثابتة: `play` و`pause` و`set_volume` و`volume_up` و`volume_down` و`reconnect` و`select_player` و`clear_log`. أما `raw_hci` و`raw_avctp` و`raw_rfcomm` و`firmware_update` و`custom_spp_write` فمرفوضة صراحة، ولا توجد لها مسارات أصلًا.
- الواجهة محمية بـ CSP صارم، ولا تستخدم أي سكربت مضمّن أو مورد خارجي. اسم الجهاز يُعرض كنص فقط، ولا يُفسَّر كـ HTML.
- **صلاحية `/dev/input`:** إضافة المستخدم إلى مجموعة `input` تسمح بقراءة **كل** لوحات المفاتيح، وليس السماعة فقط. إن أردت مراقبة الأزرار، ففكّر في قاعدة udev تمنح الصلاحية لجهاز السماعة وحده (لم تُختبر):
  ```
  # /etc/udev/rules.d/70-necklace.rules
  SUBSYSTEM=="input", KERNEL=="event*", ATTRS{name}=="oraimo Necklace Lite*", TAG+="uaccess"
  ```
- ملف الالتقاط الأصلي `necklace.cfa` يحتوي على **مفتاح الربط** (Link Key) بنص صريح. لا تشاركه، وأعد إقران السماعة إن كان قد شورك.

## 13. المرحلة الثانية: اكتشاف إمكانيات السماعة

صفحة «اكتشاف الإمكانيات» (`#/discovery`) تحوّل اللوحة إلى أداة فحص وتحليل آمنة. كل ما فيها **قراءة فقط أو مراقبة سلبية**.

### ما الذي تعرضه الصفحة؟

- **الهوية:** الاسم، والعنوان، والشركة المصنّعة، والشريحة، والبروفايلات، وحالة الاتصال الحية.
- **مصفوفة الإمكانيات:** الوظيفة | الحالة | المصدر | طريقة الاختبار | آمنة؟
  - **مؤكدة:** رُصدت في الالتقاط، أو تحقق منها الوكيل أثناء التشغيل.
  - **معلنة فقط:** مذكورة في SDP أو في قدرات AVRCP، دون دليل على عملها.
  - **غير معروفة:** لا يوجد عنها دليل بعد.
  - **موجودة:** الخدمة مسجلة، لكن بروتوكولها غير معروف.
  - **غير متاحة:** لا يمكن استخدامها حاليًا.
- **الخدمات والقنوات:** سجلات SDP، وقنوات RFCOMM، وقنوات L2CAP (PSM/CID)، وUUIDs، وكائنات BlueZ، وأجهزة الإدخال، وGATT.
- **البروفايلات:**
  - AVRCP القياسي: التشغيل، والإيقاف، ومستوى الصوت، وحالة التشغيل، ومعلومات المقطع، والأحداث المسجلة.
  - HID: الحالة «معلن لكنه غير متاح حاليًا / يحتاج اختبار اتصال آمن»، مع خريطة الاستخدامات من واصف التقارير.
  - JieLi: الحالة «خدمة مخصصة من الشركة - البروتوكول غير معروف».
- **وضع البحث:** يربط كل إجراء آمن بالحزم التي تظهر بعده.
- **السجل التفصيلي:** الوقت | النوع | القناة | الاتجاه | البيانات | النتيجة. يمكن تصفيته وتصديره.
- **التحكم المتقدم** (`#/advanced`): عرض للقراءة فقط، بلا أي أداة تحكم تفاعلية. ويضم:
  1. **فاحص إطارات RCSP:** يفكّ غلاف إطارات JieLi (`FE DC BA … EF`) من آخر التقاط محلَّل ويعرض الرمز والاتجاه والنوع والرقم التسلسلي و`XM_OPCODE` والبيانات الخام. المحتوى لا يُفكّ (جدول الرموز مجهول).
  2. **خريطة الأوامر المعروفة:** مرجع ثابت مستخرج من كود تطبيق oraimo (خصائص `GetSysInfo`، وأوامر `FunctionCmd`، ووظائف أزرار `Bluetrum KeyRequest`) بوسم «محتمل — من كود التطبيق».
  3. **تحديث البرنامج الداخلي / OTA:** يبقى معطّلاً وخارج النطاق ويحمل العبارة «لم يتم اكتشاف بروتوكول آمن لهذه الوظيفة بعد».

### «فحص آمن»: ماذا يفعل بالضبط؟

1. يقرأ حالة المحول وrfkill من `/sys/class/rfkill`.
2. يقرأ كائنات BlueZ عبر `GetManagedObjects`، ويشمل ذلك Device1 وMediaControl1 وMediaTransport1 وBattery1 وInput1.
3. يقرأ `Device1.UUIDs`.
4. **عندما تكون السماعة متصلة فقط**، ينفّذ `sdptool browse --xml --uuid 0x0100 <العنوان>` و`--uuid 0x1200`. هذه استعلامات SDP القياسية نفسها التي يرسلها BlueZ عند كل اتصال (Frames 60–264 في الالتقاط).
5. يستخرج قنوات RFCOMM وأرقام PSM من SDP، **دون فتح أي قناة**.
6. يقارن واصف HID المقروء مع الالتقاط.
7. يعرض البيانات الوصفية لخدمات GATT إن عرضها BlueZ، **دون قراءة أي قيمة أو كتابتها أو الاشتراك فيها**.
8. يقرأ `/proc/bus/input/devices` لمعرفة ما إذا كان BlueZ قد أنشأ جهاز إدخال للسماعة (AVRCP أو HID).
9. يعرض حالة ملف الالتقاط.

لا يرسل الفحص أي أمر خاص بالمصنّع، ولا يفتح RFCOMM أو L2CAP، ولا يغيّر أي إعداد.

- الأداة `sdptool` موجودة في حزمة `bluez` على Debian وUbuntu. على Fedora في `bluez-deprecated`، وعلى Arch في `bluez-utils-compat`.
- إن لم تكن مثبتة، تُستخدم نتائج الالتقاط كمرجع ويُذكر ذلك في النتيجة.

### وضع البحث: رؤية الحزم الحقيقية

يقرأ الوكيل ملف btmon **فقط**. شغّل btmon في طرفية منفصلة (يحتاج إلى صلاحية root):

```bash
sudo btmon -w ~/.cache/necklace-controller/live.btsnoop
```

بعدها **أعد الاتصال بالسماعة** حتى يرى الوكيل فتح القنوات (PSM/CID)، ثم:

1. اضغط «بدء وضع البحث».
2. لكل إجراء (تشغيل، إيقاف مؤقت، رفع الصوت، خفض الصوت، السابق، التالي، كتم الصوت):
   - **«من الحاسوب»:** ينفّذ أمرًا مسموحًا فقط: MPRIS ‏Play/Pause/Next/Previous، أو مستوى الصوت عبر BlueZ. ثم يجمع الحزم لمدة 3 ثوانٍ. الكتم غير متاح من الحاسوب.
   - **«سأضغط على السماعة»:** لا يرسل شيئًا. اضغط زر السماعة خلال 6 ثوانٍ، وستظهر الحزم التي أرسلتها.
3. لكل حزمة يعرض: الوقت، ونوع HCI، والقناة (L2CAP PSM/CID أو RFCOMM)، والبروتوكول، والـ Opcode، والاتجاه، والبايتات الخام، والمعنى، والنوع (قياسي، أو امتداد موثّق، أو خاص بالمصنّع).
4. إذا تداخلت نافذتا تجربتين، يظهر تنبيه. كرر التجربة منفردة للتأكد.

> ملف btmon يحتوي على مفاتيح الربط وحركة كل أجهزتك. الوكيل يُخفي مفاتيح الربط ورموز PIN في العرض، لكن الملف نفسه حساس. أوقف btmon بعد الانتهاء (Ctrl+C)، واحذف الملف، ولا تشاركه. ملف btmon ينمو بسرعة أثناء تشغيل الصوت (نحو 3 ميغابايت في الدقيقة).

**تحليل التقاط محفوظ:** يمكن رفع ملف btsnoop (من btmon، أو سجل HCI من Android) ليُفك محليًا. هذا هو الطريق الآمن لدراسة بروتوكول JieLi من التقاط لتطبيق oraimo الرسمي، راجع [`docs/next-experiment.md`](docs/next-experiment.md).

| POST | `/api/research/headset` ‏`{"action": "next"}` | مراقبة فقط لضغطة على زر السماعة |
| POST | `/api/media/next` و`/api/media/previous` | MPRIS |
| POST | `/api/capture/analyze` (`application/octet-stream`، حتى 64 ميغابايت) | تحليل ملف التقاط محليًا |

رسائل WebSocket الجديدة: `discovery_log` و`discovery_scan` و`research_trial` و`capture_status` و`discovery_changed`.

## هيكل المشروع

```
necklace-controller/
├── agent/            الوكيل المحلي (Python)
│   ├── main.py       نقطة الدخول والخيارات ورفض العناوين غير المحلية
│   ├── api.py        HTTP وWebSocket وطبقة الأمان

│   ├── sniffer.py    فك حزم btsnoop بشكل سلبي (HCI وL2CAP وSDP وRFCOMM/HFP وAVCTP وAVDTP وHID وATT وغلاف JieLi RCSP)

│   └── errors.py     رسائل الأخطاء العربية ورموزها
├── frontend/         الواجهة: HTML وCSS وJavaScript، مع خط Cairo محلي
├── docs/             حالة البروتوكول وتقرير الالتقاط
└── tests/            اختبارات الوكيل والواجهة ومحاكي BlueZ وsdptool وbtmon للاختبار فقط
```
